## Root-cause analysis — why did all these bugs ship undetected?

User asked for "proper analysis so we don't face issues like this." Traced each of the 7 bugs above to why nothing caught it:
- Migration `0008`: nothing checks `alembic_version == head` post-boot; a failed migration doesn't crash the app.
- e2e suite: CI's `web` job runs `npm test` (vitest) + `build` only — **zero e2e step ever existed**.
- CLI `__main__` guard: `test_cli.py` uses Typer's `CliRunner`, which calls into `app` directly, bypassing the exact code path that was broken.
- `create-admin`/`EmailStr` asymmetry: no shared validation between the CLI and the login schema; the existing test only checked DB insertion, never login capability.
- `click`/`typer` drift: no upper-bound pin on the transitive dependency, nothing exercises `--help` in CI.

Common root cause, one sentence: **tests and infra automation verify "did the mocked/bypassed path not error," not "does the real live path actually work" — and where real automation exists (migration-on-boot, deploy-on-push), failure is silent instead of fatal.**

**Separate finding surfaced while checking CI**: read `.github/workflows/ci.yml` in full and found a SECOND workflow, `deploy.yml`, that runs on every push to `main` on a `self-hosted` runner (`C:\Calibration\deploy-package\deploy.ps1` — Windows, matches the `.claude/settings.json` mystery from 2026-09-18), with **no dependency on the `api`/`web` CI job passing**. Checked `gh run list --workflow=deploy.yml`: every run since 2026-09-16 shows `queued` → sat for exactly 24h0m → `cancelled`, including the run my own push just triggered. `gh api repos/.../actions/runners` → `{"total_count":0}` — **zero self-hosted runners currently registered**. So pushing to `main` has had no actual production effect in 6 days. Not investigated further (whose machine, why disconnected) — flagged prominently in `HANDOFF.md`, tied to the existing Windows-session open question.
