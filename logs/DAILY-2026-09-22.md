## Live testing — found real infra gaps, unrelated to the redesign

- Docker `web` container was 6 days stale (pre-merge image). Rebuilt (`docker compose build web && up -d web`) — safe, doesn't touch DB/api.
- **Found: DB migration `0008_add_failure_reason` never actually applied** to this container's Postgres, despite the API's startup log claiming it ran. `alembic_version` was still `0007_fix_batch_names`. Every request touching `logger_results` (Overview, History, Run Detail) 500'd as a result — `psycopg.errors.UndefinedColumn: column logger_results.failure_reason does not exist`. Root-caused by exec'ing into the container and reproducing the query directly (docker logs showed no traceback — access/exception logging appears suppressed in this env). Fixed by running `alembic upgrade head` directly against the running container; this is an operational DB catch-up, not a code change.
- Also found: `apps/api/ite_api/cli.py`'s `create-admin` command silently no-ops under `python -m ite_api.cli` — no `if __name__ == "__main__":` guard, so the module just imports and exits 0 without running anything. The real entry point is the installed console script (`ite-api`, from `[project.scripts]` in `pyproject.toml`). Not fixed (pre-existing, out of scope for today) — flagged for later.
- Also found: the backend's `EmailStr` validation rejects reserved TLDs (`.local`, `.invalid`) — hit this twice, once with my own test account, once with the e2e suite's baked-in `boss@ite.local` seed credential.
- Dev-server proxy (`vite.config.ts` → `http://localhost:8000`) doesn't work for live testing here: the `api` container's port 8000 isn't published to the host (only `edge` on port 80 is). Node's http-proxy inside the vite dev process also failed to reach `127.0.0.1:80` even though raw `curl`/`node -e` from the same shell could — never root-caused (looked like a sandbox-specific restriction on the vite child process, not a real proxy bug). Abandoned the dev-server approach in favor of rebuilding the Docker `web` image, which worked cleanly. `vite.config.ts` edits made during the failed attempt were reverted (`git checkout --`), nothing committed from that path.
